## Hypotheses, predictions, pass/kill (each fixed before the run)
1. quadratic-all-pairs-pair-term (primary): the bench's chunked all-pairs pair term is O(N^2) and is the blow-up. Predict (guess, untested): pp_acc is >=90% of per-force time at 1e5; exponent of bench-path-chunked-eager 1e4 to 1e5 about 1.8-2.0; 3e5 about 5.4 s per tick and 1e6 about 60 s (guess: scaled by N^2 from the logged 597 ms). PASS: pp_acc share at 1e5 >= 80% AND exponent of pp_acc ms in [1.7, 2.1] for both 1e4-1e5 and 1e5-1e6 (1e6 only if it finishes; if it is skipped or OOM, 1e5-3e5). KILL: share < 50% or exponent < 1.5. One window in, one out: INCONCLUSIVE.
2. density-crowding-in-cell-path (secondary, about the production fast paths, not the bench path): fixed-box occupancy growth makes cell (candidate width = max occupancy, scatter_field.py:324-358) O(N^2) too, and adapt only partly spared. Predict (guess, anchored on logged 253 ms cell and 193 ms adapt at 1e5): cell fixed-box ms at 1e5 >= 5x cell constant-density ms; cell constant-density exponent <= 1.2; adapt constant-density ms(1e6)/ms(1e5) <= 12. PASS (crowding explains cell cost): cell ratio fixed/density at 1e5 >= 5 AND density exponent (1e4-1e5) <= 1.2. KILL: ratio < 2. Separate adapt line: PASS linear if ms(1e6)/ms(1e5) <= 12 at constant density; KILL if >= 30.
3. first-force-bench-artifact: the bench's per-tick number includes one extra force per run_model call (1.33x at 1e5, 1.1x at 1e4) and a 2-rep median. Predict: bench-repro-run-model at 1e5 within 15% of 597 ms (bench.json reproducible) and repro/bench-path-chunked-eager ratio at 1e5 in [1.15, 1.40] versus [1.0, 1.15] at 1e4. PASS: both. This hypothesis can explain at most about 1.2x of the 87x; it is checked, not expected to be the cause. If repro is outside 15% of 597 ms, bench.json is not reproducible (report that, no further verdict on 1).
4. 3d-cheapness-from-cell-cap-truncation: the 3D 1e5 cost is bounded because pair_acc keeps only 32 candidates per cell while 50% of bodies sit in cells over the cap. Predict: voxel-3d fixed-box cell_overflow_cells_runtime at 1e5 > 0 (CPU count says 589 cells over 32 at the initial state); pair_acc ms per force 1e4 to 1e5 ratio <= 14. PASS: overflow > 0 at 1e5 AND ratio <= 14. KILL: overflow == 0 at 1e5 (then truncation plays no role). Whether truncation damages 3D accuracy is untested here (no accuracy scoring).
5. bandwidth-and-path-switch (curiosity, no verdict): no N-dependent path switch exists in the bench path (chunked is chosen once, dense N<=512 only for stock, adapt threshold adapt_n=50000 applies only with the auto/adapt opts). Record peak memory and ms per 2e8-element chunk; no pass/kill.

Tie-break for ranking when several PASS: larger share of the 1e5 per-force time wins; for an argmin/exponent fit use the two-point slope above, no regression. Convergence/accuracy ratios are against nothing numerical (timing only), so the error-floor clause does not apply.
