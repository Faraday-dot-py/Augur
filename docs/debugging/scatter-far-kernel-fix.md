# Fixing the learned far-field kernel `kmlp(r)` beyond its trained range (scatter-field, Exp E)

Branch `far-kernel-fix` (from tiling branch head 4c58332). Code: `scripts/scatter_far.py` (kernel specs + `install`, swaps `model._kernel_fft`; nothing in `scatter_field.py` / `scatter_tiling.py` edited), `scripts/scatter_far_eval.py`, `scripts/scatter_far_train_kernel.py`, job scripts `scripts/polaris_far/`. Remote `~/augur_far` (copy of `~/augur_tile2`); frozen reference checkpoint copied to `~/augur_far/kern/E_frozen.pt` (Exp E = `E_ms_kp_pot_v_g128`, sha256 logged in the R0 job). Raw results `results/far_*.json`.

Definitions. err@k = mean position error per body at tick k vs exact fp64 all-pairs softened gravity (eps .5, G=1), sim units. Wide scene = 4x4 tiles of 64 (extent 256, halo 16, tile copy G=192), N=4800 Gaussian sigma 32 warm (vfac 1), seeds 4738 (dev only), 9000 and 12000 (held out). Far term = coarse global grid (cell far_c*h, far_c=4 -> 2 units) carrying the kmlp convolution of all mass minus the tile box's own coarse potential. F(r) = inward force of a unit-mass pair at separation r = dK/dr (K the potential kernel incl. the pp split factor); true F = r/(r^2+.5^2)^1.5. "ratio" = F/F_true.

## Constraints and pass/kill (set by user, recorded before any run)
- Kernel: ratio within +-10% for every r in [1, R_max] (R_max >= 256, I use 512), never repulsive, monotone decaying beyond r=32, r<=32 within 2% of the old kernel. Note: below r~4 the pair term (pp, window r<2) carries part of the force and the kernel alone is .74 at r=2 by design; I check the +-10% band on [4, 512] and the "unchanged" band (2% of the old force) on [1, 32]. Flagged interpretation.
- Primary: tiled+far err@20 on the wide scene, held out 9000/12000, <= 0.4 (ceiling .18, current 3.56). Also err@5/10, difference to single G=512 grid.
- No regression (+5%): extent-128 single-grid and 2x2 / 4x4-of-32 tiled held-out rows (err@5/10/20, force error by seam distance, dP); dE@100/1e3 for nr100, bh300 (job 3323) <= 1.05x; |v|<c unchanged. Cost: far term <= +1 ms/tick over today's +0.7, memory +10%, O(N).
- KILL: any no-regression row fails, or tiled+far err@20 > 1.0 after the rung's attempts. R3/R4 additionally must beat best kernel-only rung by >= 20% at <= +25% tick cost.
- Rules: no hard-coded conservative forces in the shipped fix (hand clamps and the analytic splice are labelled DIAGNOSTIC REFERENCES only), soft priors OK, stay O(N), pp=2, one GPU job at a time, held-out seeds for any selection.

### R1: retrain kmlp only (4,417 params; U-Net, pair term, everything else frozen) on r in [1, 640] (job 3797; train 90 s, 30k Adam steps; `scripts/scatter_far_train_kernel.py`, kernel `results/far_kernels/r1_mlp.pt`)
Design (stated before running). Same architecture (2 -> 64 -> 64 -> 1 GELU, input (r, log(r+.5)), times the pp split factor), initialised from the shipped kmlp. Targets: r <= 28 the shipped kernel (potential K and force) so the interior is unchanged; r >= 48 the exact softened force r/(r^2+.25)^1.5; smoothstep blend of the two forces between. r sampled log-uniformly on [1, 640] plus uniform [0, 34]. Loss: relative force error (r >= 4, clipped at 5), absolute force error below 4, 100 x (K - K_old)^2 on r <= 28 (anchors the constant), soft hinge against F < 0 (the only prior; no decay law is imposed, the decay comes from the exact-force targets). Training data = a known function evaluated at sampled r, i.e. supervised distillation of the exact softened law, not a hand-built kernel; the shipped model is the MLP. Checkpoint chosen by the force-ratio score on a dense validation grid (no scene seeds involved).
Prediction (before running): max |ratio-1| over [4,512] 5-15% (plain MLP on raw r over 2.5 decades is a stretch), r<=32 within 2%, tiled+far err@20 .18-.25, ~55% chance of meeting the +-10% band.

### R2b: structurally constrained tail (job 3813; kernel `results/far_kernels/r2b_tail.pt`)
Trigger: R1 met the tail criteria on [4,512] but is only +-6% to 1500 and is not guaranteed positive; R2 asks for architecture rather than tuning. Design: shipped kmlp frozen for r <= 32 (interior bit-identical, deviation 0), beyond r0 = 32 the FORCE is a learned MLP in log space F(r) = exp(g(log(r/32))) (positive by construction, no decay law assumed; g trained 8000 steps to log F_true over r in [32, 4096], final log-force MSE 5e-7), K(r) = K(32) + cumulative trapezoid of F on a 2048-node log table (smax 4096), linear interpolation. Params: 4,353 new (g) + the frozen 4,417. Caveat on generality: exp() forbids a repulsive tail, which suits gravity but would block a model meant to learn repulsive uneven forces; the plain MLP kernel (R1/R1b) has no such constraint (flag for the user).
Prediction: ratio within 1-2% on [32, 1500], system err@20 = R1's (.168, ceiling), cost +0.1-0.5 ms.
Result: ratio .930 at r=4 (shipped value) and 1.000 +- .004 for r >= 32 out to 1500; monotone 32..512; min force 4.0e-7; wide scene err@5/10/20 .018/.053/.168 (R1: same), 64 tiles .029/.090/.306 (same). Gain over R1 on the primary metric: 0 (<1%); the benefit is only tail exactness and the structural sign/interior guarantees. Time: see final cost table.
