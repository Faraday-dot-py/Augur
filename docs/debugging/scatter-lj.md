# Scatter field on 2D Lennard-Jones MD (branch lj-scatter-field, from far-kernel-generalization b2a0522)

Question: can the Exp E mesh model (`ms_kp_pot_v_g128`: U-Net on a grid, FFT kernel, pp=2 knn pair term, potential head, Verlet), run tiled, reproduce the six `lj_sim.py` scenes with the same metrics as the LJForceDynamics entry (experiment-log "2D Lennard-Jones MD", v2)? That model was a dedicated radial pair-force net; this tests the generic scatter field.

## Mapping onto the scatter-field grid
- Lengths / LS, LS = 1.25: the shifted-force cutoff rc = 2.5 sigma becomes the model pair radius pp = 2.0 (the stock window `(1-(r/pp)^2)^2` then spans exactly the LJ interaction); sigma = 0.8 model units, grid cell h = 0.5 (0.625 sigma). Time unchanged; v and a scale by 1/LS and LS. Frame = 20 truth steps = 4 model steps of dt 0.025 (stock dt is 0.1; 4 substeps/step in the gravity truth, here the model step is finer because LJ time scales are ~0.1 tau).
- Boundary: periodic. The box is cut into cores of side <= 20 model units (e.g. N=2688 liquid: 2x2; gas: 10x10). Each tile runs one copy of the model on G = 64 (extent 32, h 0.5, same cell as Exp E's G=128/extent 64) centred on its core; it receives periodic ghost images of every body within the extended square (halo >= 6 units >> pp=2). Only own bodies keep their force; the recurrent field stays tile-local; the mean (momentum) removal is global. This is the same ghost-exchange scheme as `scatter_tiling.py` with wrap-around neighbours; no far term (rc is finite, so the halo is exact, unlike gravity). Cost O(N + tiles*G^2); the pair term is per-tile knn-24 within pp.
- Not used: min-image all-pairs, any analytic LJ force, hard-coded antisymmetry/conservation. Energy/pressure are measured with the TRUE LJ potential evaluated on the model trajectory (as lj_eval does with the model's own stats it is the model state that matters; here E/N offset therefore measures state drift, not a learned-potential integral, so it is not directly comparable to the LJForceDynamics E offset; see caveat).

## Zero-shot vs retrain
Zero-shot (Exp E, gravity) is expected to fail: no repulsive core, wrong scale, and dt/units differ. It is run as a floor. Minimal fair retrain: finetune all Exp E weights (kernel MLP, pair MLP, U-Net; none frozen, none replaced) on small periodic LJ boxes with the same data protocol as `train_lj.py` (rho log-uniform 0.05-1.05, band 0.62-0.82 held out, T 0.2-2.5, 15% hot/dense scenes rho .9-1.05 T 2-5 to put d<1.2 into data; boxes one tile, N 120-400; free rollout k 8 -> 32 model steps; loss 100 pos + vel). Arm `scratch` (stock zero-init heads, no gravity prior) as the control for whether the gravity init helps. Liquid (0.70) and quench (0.80) sit in the held-out density band; solid/melt/coexist/gas are in-distribution densities but whole-box scenes at N=2688 (bigger than any training box, which tests tiling/size generalisation).
Requirements check: O(N) (cell-list-free grid scatter + local knn); tileable (periodic tiles, scenes 16x larger than training boxes); no hard-coded conservative force (loss is trajectory only; no energy term, none conserved by construction except mean-momentum removal); no pp=8 or O(N^2) pairs.

## Evaluation (comparable to lj_eval)
Same truth npz (`results/lj_*.npz`, seed 4738, 800 frames), same functions (`lj_eval.summary/err_curve`): last-200-frame T, psi6, P, E/N, g(r) (rel L2), mean position error at frames 1..100 against the truth-rerun chaos floor. Energy/pressure/T are computed with the true LJ on model states (T from KE; P from KE + true virial), so an unphysical state shows as huge P. Also two-body force curve (full model vs truth, and pair term alone) for d 0.75-2.5.

## Result 2026-10-23 (KILL both arms)
Result (2026-10-23, Polaris jobs 3916 ft, 3917 scratch, one GPU each, 6000 it, 0.18 s/it = ~18 min train + ~7 min eval per arm; est. had been 1-1.7 h; seed 4738; results/scatter_lj_{zeroshot,ft,scratch}.json, scored by scripts/score_scatter_lj.py). T = temperature, psi6 = hexatic order, P = pressure, err = mean position error per body at frame 20 (v2 = LJForceDynamics).
- zeroshot: KILL as predicted (T 12-2000x truth, P ~1e30+ in all six scenes).
- ft: KILL (T off >5% in gas .22, liquid .60, coexist .54, solid .97, melt .056; passes only quench: T .023, psi6 .008, P .21). psi6 off >.03 in liquid (.80 vs .51 truth). P within 10% only in melt (.021). Frame-20 error 1.2-4.4x v2 (liquid .159, coexist .144, quench .387, solid .0087, melt .0058, gas .0091), not >5x in any scene.
- scratch: KILL (T off >5% in gas .48, liquid .18, coexist .41, solid .87; passes quench and melt; melt T .037, P .028). Frame-20 error 1.5-4.2x v2. Scratch roughly equal to or better than ft on T/psi6/g(r) (liquid g(r) rel-L2 .05 vs .69), so gravity init did not help (prediction held).
- Frame review (fresh agent, ft rollouts): solid cools to near-frozen (T .007 vs .214) and stays a clean lattice; liquid and quench develop voids/dense network (cavitation-like) by frames 150-800; melt heats up late; coexist coarsens into clumps and filaments. Energy is not conserved by the model: systematic T drift (heating in melt, cooling in solid), no thermostat-free stability.
Verdict: KILL for both arms by pre-registration; generic scatter field, finetuned or from scratch, does not reproduce LJ thermodynamics with the 6000-it protocol. Short-horizon trajectories are within 1.2-4.4x of the dedicated pair-force net, so dynamics are partly learned but there is a slow T/density drift. Do not re-try: same protocol with more iterations; next would be an energy/drift-aware term or longer k, not tried.

Measured: 0.18 s/it at k up to 32 (replaces the unmeasured estimate above).

## Diagnosis 2026-10-23 (why both arms KILLed; Polaris diag jobs 3918/3919 ft/scratch, 3920/3921 warm-field + pair-only eval; seed 4738; no training)
Scripts: `scripts/scatter_lj_diag.py` (force at truth states split into pair term / mesh term, NVE rollout ablations, true-force Verlet at dt .025, tiled vs single-tile, knn truncation counts, training-data coverage), `scripts/scatter_lj_eval_paironly.py` (full six-scene eval with the mesh branch off at inference). Results `results/scatter_lj_diag_{ft,scratch}{,_warm}.json`, `results/scatter_lj_{ft,scratch}_paironly.json`. Definitions: E/N = true-LJ energy per body of the model state (conserved by truth in NVE scenes: gas, liquid, solid, coexist); pair term = the knn-24 pp=2 window MLP; mesh branch = U-Net on grid (density + two velocity-density channels + recurrent potential field) plus FFT kernel; "pair-only" = mesh branch set to zero at inference, weights untouched.

Verdict: the failure is the mesh branch, not the pair term. The pair term alone is almost the right physics; the mesh branch adds a ~1%-of-force, velocity- and history-dependent, non-conservative force that steadily pumps energy in or out.

Ranked causes
1. Mesh branch injects non-conservative, velocity-dependent force (root cause, strong evidence).
   - 160-frame NVE rollouts from truth frame 0, change in E/N (truth: 0.000): ft full vs pair-only: liquid -0.256 vs -0.009, solid -0.286 vs +0.003, coexist -0.255 vs -0.023, gas -0.063 vs -0.016. scratch full vs pair-only: liquid -0.043 vs +0.004, solid -0.184 vs +0.003, coexist +0.078 vs -0.013, gas +0.098 vs 0.000. Sign differs by arm and scene (ft cools the gas, scratch heats it): a random-signed bias, not a learned physical drag.
   - Gas has 1.0 neighbour inside rc on average, so gas drift cannot come from pair interactions; it is the mesh acting on free particles.
   - Full 800-frame eval with mesh off (no retrain), T error vs truth: ft full -22/-60/-97/-54/-6/-2% (gas/liquid/solid/coexist/melt/quench) becomes -2.2/-2.7/-1.5/-3.7/-0.1/0.0%; scratch full +48/-18/-87/+41/-4/-1% becomes 0.0/0.0/-1.5/-2.4/0.0/0.0%. liquid psi6 .80 (ft full) -> .505 (truth .510); g(r) rel-L2 liquid .69 -> .015, solid .82 -> .011; P within 11% in liquid (ft .288, scratch .355 vs .325), melt +7%. So most of the KILL (T, psi6, g(r)) disappears when the mesh is removed.
   - Mechanism size (warmed recurrent field, truth states): median mesh force .03-.09 per body (about 0.2-1% of |a_true|) against pair-term error .06-.10 in the same bins; mesh work rate -0.025 per body in solid vs KE/N .20 gives an e-folding time of ~8 time units, matching the observed cooling over 16.
   - Velocity channels are the carrier: zeroing the scatter velocity channels at inference (out of distribution, upper bound) gives liquid dE +0.003 (ft), coexist +0.004, gas +0.006; solid +0.038/+0.021 left, so the recurrent history also contributes. Forcing the recurrent field to zero is catastrophic (T -> 0.03 in liquid): the net relies on that state.
2. Training is blind to it, and the eval states are mostly outside the training temperature range (enabler).
   - Val loss plateaus: 3.17, 0.279, 0.155, 0.102, 0.083 at it 500..2500, 0.074 at it 6000 (job 3916); not an undertrained-iterations problem. Per-batch loss spans 1e-3..0.25 (pos 8e-6..5e-4), dominated by hot chaotic scenes; a 1% systematic force over the 32-step (0.8 time) window changes velocities by a few percent in a cold solid, roughly 1e-3 in the velocity term vs val ~0.07 (estimate, not measured separately).
   - Coverage (cache of the 320 training scenes, within 15% of density and 30% of T): liquid 1, solid 1, melt start 0, quench end 0, gas 4, coexist 4; realised T 5/50/95th percentile .65/1.66/2.60, none below 0.1. Cold states are essentially unseen, so nothing constrains the mesh bias where it matters most (solid, liquid, quench end).
3. Pair-term precision limits trajectory error but not thermodynamics (secondary).
   - Pair-term force error vs truth at truth states: relative L2 .8-6% (median bins: ~1% for nearest-neighbour distance 1.0-1.2 sigma, ~3% for .9-1.0). Pair-only err@20 (frames) ft/scratch vs v2: liquid .168/.176 (1.7-1.8x), coexist .214/.180 (1.5-1.8x), quench .349/.356 (1.8x), melt .0063/.0057 (3.8-4.2x), gas .0079/.0011 (<=2.6x), solid .0125/.0119 (8x). Full-model values are the same within noise, so trajectory error is not caused by the mesh. Whether more training or a different pair parametrisation lowers it is untested.
   - Pair-only passes the pre-registered "not KILL" gate (T <= 5% all six, psi6 <= .03, err@20 <= 5x v2 in 5/6 scenes) in both arms, i.e. PARTIAL, not PASS (T 1% gate missed in 4/6 scenes).

Ruled out (each checked individually)
- knn-24 truncation: no body has more than 24 neighbours inside rc in any scene/frame (liquid 13.5, solid/melt 18, quench 16.5 mean); knn 64 gives identical rollouts (ft liquid dE -0.256 vs -0.256).
- Core steepness d < 0.9 sigma: only 0-0.2% of bodies have a nearest neighbour below 0.9 in any scene (melt late 0.19%). The two-body curve is indeed wrong there (ft/scratch 332 vs true 1841 at d=.75, 176/179 vs 291 at .86) but it is not reached.
- Grid h=0.5 vs sigma=.8 (CIC smoothing): the pair window already covers the whole interaction, and pair-only is accurate; the mesh adds nothing useful, so resolution of the mesh is moot.
- Integrator mismatch (dt .025 Verlet with the TRUE force, 160 frames): dE/N gas +0.0096, liquid -0.0026, solid +0.0032, coexist +0.025 vs observed -0.06..-0.29: at most 10% of the drift, and the sign is opposite for coexist.
- Tiling/ghost bookkeeping: pair-only tiled rollouts conserve E, and pair-term-only forces are layout-independent (tests). Single-tile vs tiled full-model forces differ 0.7-1.8% (ft) / 0.2-1.0% (scratch) rel-L2, all from the mesh; second order.
- Eval pipeline: truth E drift at dt .005 is <=0.0003 over 160 frames, truth-rerun error at frame 20 is 1e-4 (liquid); pair-only through the identical pipeline reproduces truth T, psi6, g(r), P. The first diag pass evaluated forces with a zero recurrent field and showed mesh forces of 20-36% of truth and power -1.3..-8: an artefact of the unrepresentative zero-field state (confirmed by the warmed re-run, mesh .2-1%); rollout ablations are the reliable test.
- Undertraining by iteration count: see cause 2 (val plateau). Scratch >= ft is explained: the gravity init contributes nothing the pair term needs.

Requirement notes: the pair term is radial with one shared g(r) per pair (reciprocity by construction, as in v2 and in the stock Exp E); pair-only is therefore essentially the v2 radial net with a window, and the "generic scatter field" claim for LJ reduces to "its pair term works, its mesh is harmful". No analytic LJ force was used in the model; analytic LJ was used only in diagnostics (truth).

## Proposed fix and pre-registered test (NOT run)
Smallest architectural change: make the mesh branch a function of positions only and memoryless, so its force is -grad of a learned potential of the density field (no velocity input, no recurrent field), hence no net work around a closed path. This is a constructor switch on the existing model (`vel_in=False`, `recurrent=False`), not a new component. Rationale: LJ has finite range so the halo is exact and the mesh is not needed for accuracy; it must at least not be able to do work.
Arms (one change per run vs the frozen scratch baseline `results/scatter_lj_scratch.json`; scratch init because scratch >= ft; seed 4738, protocol identical to this branch, 6000 it, ~20 min each): (a) vblind = velocity channels off; (b) norec = recurrent field off; (c) paironly = no mesh branch (control for whether the mesh adds anything). Run ft init only for an arm that passes.
PASS per arm: in all six scenes |T-T_truth|/T_truth <= 5%, |psi6 diff| <= .03, |P diff|/|P_truth| <= 15%, and in the four NVE scenes |dE/N| <= 0.03 over 160 frames; err@20 <= 5x v2 in >= 5/6 scenes. KILL: any scene T off > 5% or |dE/N| > 0.1 over 160 frames. Interpretation: (a) or (b) passing and (c) matching means the mesh is unnecessary for LJ; (a) and (b) failing but (c) passing means the mesh branch cannot be made harmless without removing it. Secondary (data, only if an arm passes narrowly): add cold scenes (T .05-.4, rho .6-1.05) to the training mix. Reference to beat: post-hoc pair-only (this diagnosis) T -3.7%..0%, E drift <= 0.023.
